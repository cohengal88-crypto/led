# אפיון פרויקט – LED IT BE (jacob group)

> מסמך חי. מתעדכן בסוף כל שלב. גרסה 2 (28.10.2026): המודל העסקי הוגדר מחדש והפרויקט נבנה מהתחלה.

## 1. מודל עסקי

האתר הוא **קטלוג מוצרים בלי מחירים** ומנגנון **בקשת הצעת מחיר (RFQ)**. אין רכישה אונליין בשלב הזה.

| מי | מה עושה |
|---|---|
| **מבקר / לקוח** | גולש בקטלוג, מסנן ומחפש, נכנס לדף מוצר, בוחר וריאנט (גוון / CCT) וכמות, ומוסיף ל"סל הצעת מחיר". בסוף ממלא פרטים ושולח בקשה. **אין צורך בהרשמה.** |
| **מנהל האתר** | מתחבר ללוח ניהול, מוסיף, עורך ומסתיר מוצרים (כולל תמונות ו-Datasheet), ורואה את הבקשות שנכנסו עם סטטוס לכל אחת. |
| **בעל העסק** | מקבל **מייל** על כל בקשה חדשה, עם רשימת המוצרים ופרטי הלקוח. |

**לעתיד (לא בשלב הזה):** מחירים (לכולם או רק ללקוחות מחוברים), אזור לקוח עם היסטוריית בקשות, ורכישה אונליין. מבנה הנתונים מוכן לזה מראש: לכל מוצר יש שדה `price` ריק, ו-`showPrice=false`.

## 2. מה למדנו מאתרים עם אותו מודל

נבדקו אתרי יצרני ומפיצי מודולי LED לשילוט (SloanLED, HanleyLED, Luxeon Star), מערכות RFQ ל-B2B (Cart2Quote / Magento, Shopify B2B, commercetools) ומאמרי UX על Quote Cart.

| עיקרון | איך זה בא לידי ביטוי אצלנו |
|---|---|
| זרימה מוכרת של סל קניות, רק שבמקום "לתשלום" יש "שלח לקבלת הצעת מחיר" | כפתור **"הוסף להצעת מחיר"** בכל כרטיס ובכל דף מוצר, ואייקון סל עם מונה בכותרת של כל העמודים |
| קונה B2B צריך מפרט לפני שהוא שואל מחיר | **דף מוצר מלא**: טבלת מפרט, Ordering Guide, פיזור אופטי, מידות, הורדת Datasheet PDF |
| בחירת קונפיגורציה לפני הבקשה | בחירת **וריאנט** (Cool / Pure / Warm White וכו') וכמות לפני ההוספה לסל |
| טופס קצר. רק מה שצריך כדי לתמחר | שם, חברה, טלפון, מייל, הערות לפרויקט (כמות שנתית, מועד, סוג שלט) |
| אישור מיידי ומעקב | מסך תודה עם מספר בקשה, מייל לבעל העסק, ובלוח הניהול סטטוסים: חדשה / בטיפול / הצעה נשלחה / נסגרה |
| מענה מהיר מנצח עסקאות | הבקשה מגיעה במבנה קבוע (מוצר, וריאנט, כמות) כדי שאפשר יהיה לתמחר מהר |
| ערוץ מקביל למי שלא רוצה טופס | כפתורי WhatsApp וטלפון זמינים תמיד |

## 3. ארכיטקטורה

| שכבה | בחירה | למה |
|---|---|---|
| Frontend | **Vite** (multi-page) + JavaScript רגיל (ES modules) + CSS | שומר על ה-HTML וה-CSS הקיימים (העיצוב נשמר), בלי framework כבד. build מהיר |
| Database | **Firebase Firestore** | מוצרים ובקשות משותפים לכל המבקרים |
| התחברות מנהל | **Firebase Auth** (מייל + סיסמה) + רשימת מנהלים ב-Firestore | במקום הסיסמה `1234` שהייתה כתובה בקוד |
| תמונות ו-PDF | **Firebase Storage** | ⚠️ דורש תוכנית **Blaze** (צריך להזין כרטיס אשראי), אבל בשימוש קטן זה נשאר בחינם. מומלץ להגדיר התראת תקציב של $1 |
| מייל על בקשה | **Web3Forms** (חינם, 250 בקשות בחודש) | נשלח ישירות מהטופס, בלי שרת. הבקשה נשמרת גם ב-Firestore |
| אחסון האתר | **Firebase Hosting** | חינם, HTTPS, דומיין משלך |
| בדיקות | **Playwright** (e2e, desktop + mobile) | רצות לפני כל push |
| מצב Demo | שכבת נתונים כפולה: Firebase אם יש הגדרות ב-`.env`, ואם אין, נתוני דמו בדפדפן | אפשר לפתח, לבדוק ולהציג תצוגה מקדימה גם לפני שחשבון Firebase מוכן |

### מבנה תיקיות
```
led/
├─ index.html            דף הבית
├─ catalog.html          קטלוג
├─ product.html          דף מוצר (?id=)
├─ quote.html            סל הצעת מחיר + טופס
├─ admin/index.html      לוח ניהול
├─ src/
│  ├─ styles/            tokens, base, ו-CSS לכל עמוד (מהעיצוב הקיים)
│  ├─ components/        header, footer, toast
│  ├─ lib/               quote-cart, i18n, data/ (demo | firebase)
│  └─ pages/             JS לכל עמוד
├─ public/               תמונות, favicon, seed של מוצרים
├─ firebase/             firestore.rules, storage.rules
├─ tests/e2e/            בדיקות Playwright
├─ legacy/               הקבצים הישנים, לעיון בלבד, יימחקו בסוף שלב 2
└─ docs/SPEC.md
```

### מודל נתונים (Firestore)
```
products/{id}            // מוצר = משפחה של מק"טים שנבדלים רק בצבע / גוון / אורך גליל
  type                   // modules | bars | strips | neon | pixel | controllers | accessories
  name {he, en}
  skus[]                 // כל המק"טים של המוצר, ממוינים
  variants[] {sku, he, en, hex, source}   // source = השם המקורי מהאינדקס
  specs[] {he, en, value}
  images[], datasheetUrl // תמונות לפי מק"ט יתווספו מלוח הניהול (שלב 4)
  published (bool), order (num),
  price (null), showPrice (false)          // לעתיד
  createdAt, updatedAt

quoteRequests/{id}
  number ("Q-2026-0001"), status (new|in_progress|quoted|closed),
  customer {name, company, phone, email, notes},
  items[] {productId, model, variant, sku, qty},
  createdAt

admins/{uid}  { email }
```

### הרשאות (Security Rules)
- `products`: קריאה לכולם (רק מוצרים עם `published`), כתיבה רק למנהלים.
- `quoteRequests`: כל אחד יכול **ליצור** (עם ולידציה על השדות), רק מנהלים יכולים לקרוא ולעדכן.
- `storage`: קריאה לכולם, העלאה רק למנהלים (תמונות עד 5MB, PDF עד 20MB).

## 5. מה נשמר ומה יורד מהגרסה הקודמת
- **נשמר:** כל העיצוב (צבעים, פונטים Assistant/Inter, hero, כרטיסים, כרטיסי המפרט של המוצרים), דו-לשוניות עב/En, תוכן דף הבית, 6 המוצרים (בקטלוג הישן היה כתוב "16 דגמים", אבל בפועל היו 6).
- **יורד:** פורטל לקוחות עם ח.פ וסיסמה, מחירונים ללקוח, ההזמנות ב-localStorage, וסיסמת המנהל בקוד. כל אלה מוחלפים במודל הצעת המחיר ובלוח ניהול מאובטח.

## 6. מה צריך ממך (עד שלב 4)
1. לפתוח פרויקט ב-[Firebase Console](https://console.firebase.google.com), להעביר אותו לתוכנית Blaze ולהגדיר התראת תקציב.
2. ליצור Web App ולשלוח לי את ה-`firebaseConfig`. אלה מפתחות ציבוריים, לא סודיים.
3. לפתוח מפתח ב-[Web3Forms](https://web3forms.com) עם המייל שאליו יגיעו הבקשות.
4. פרטי קשר אמיתיים: טלפון, WhatsApp, מייל וכתובת.

## 7. יומן שלבים
- **שלב 1 (28.10.2026):** שלד Vite, דף הבית עבר עם עיצוב זהה (נבדק בהשוואת פיקסלים), סל הצעת מחיר משותף עם מונה בכותרת (גם במובייל), עמוד סל בסיסי, שכבת נתונים demo/firebase. הקטלוג הישן מחובר זמנית לסל החדש עד שלב 2. תוקן באג: בגרסה הישנה אי אפשר היה להחליף שפה במובייל. 27 בדיקות עוברות.
- **שלב 2 (28.10.2026):** 6 המוצרים עברו מה-HTML הישן ל-`public/data/products.json` (מפרט, Ordering Guide, וריאנטים, אריזה, שרטוטים). קטלוג חדש: חיפוש סלחני לרווחים ולמקפים, סינון לפי קטגוריה ומותג, הסינון נשמר ב-URL, ומצב "אין תוצאות". בכל כרטיס בוחרים וריאנט וכמות ומוסיפים להצעת מחיר. דף מוצר מלא (`product.html?id=`): לחיצה על שורה ב-Ordering Guide בוחרת את הוריאנט. כותרת ופוטר עברו ל-partials משותפים (`src/partials/`). תוקנו באגים: כיוון הטקסט בגיליונות המפרט (בגרסה הישנה היה מוצג "W/PCS 1.08" במקום "1.08 W/PCS"), ופס הסינון במובייל שתפס חצי מסך. 53 בדיקות עוברות.
- **שלב 3 (28.10.2026):** טופס הצעת מחיר בעמוד הסל: שם, חברה, טלפון ומייל, ופרטי פרויקט לא חובה (סוג, כמות שנתית, מועד). בדיקת שדות בעברית עם מספרי טלפון ישראליים (נייד, קווי, 07X, +972). מסך תודה עם מספר בקשה (Q-שנה-מספר רץ), והסל מתרוקן. נוספו: זכירת פרטי לקוח לפעם הבאה (עם "לא אתם? נקו פרטים"), טיוטה שלא נמחקת ברענון, ורמז לאריזה ("שקית = 100 · קרטון = 2,500" עם כפתור עיגול) בעמוד הסל ובדף המוצר. שדה מלכודת נגד בוטים. טופס צור קשר בדף הבית במקום כפתורי ה-mailto. המייל במצב דמו: `src/lib/notify.js` יעבור ל-Web3Forms כשיוגדר `VITE_WEB3FORMS_KEY`. תוקן באג: כפתור Contact בתפריט האנגלי היה בלתי נראה (טקסט כהה על רקע כהה). 90 בדיקות עוברות.
- **שלב 3א (28.10.2026):** הקטלוג נבנה מחדש מאינדקס הפריטים. הסקריפט `scripts/import-products.py` מקבץ את 671 המק"טים ל-171 מוצרים, כך שמק"טים שנבדלים רק בצבע, בגוון, באורך גליל או ב"דגם 2" הופכים לגרסאות של אותו מוצר. הקטגוריות נקבעות לפי סוג המוצר ולא לפי קוד המיון, כי קוד 150 מערבב מודולים, סרטים וניאון. דולגו שורות שאינן מוצרים: 15516 (לא פעיל), 15601 (הנחה) ו-15701 (עמלות). 6 המוצרים של JDS ו-Talent הוסרו לבקשתך. אין תמונות בשלב הזה: במקומן מוצג איור לפי סוג מוצר בצבע של הגרסה. חיפוש לפי מק"ט בוחר את הגרסה המתאימה. הקטלוג נטען 24 מוצרים בכל פעם. המק"ט נשמר בסל ובבקשה. נגישות: בדיקת axe-core (WCAG 2.1 AA) בכל העמודים בעברית ובאנגלית, ותיקוני ניגודיות בעיצוב המקורי. רמז האריזה לא פעיל, כי באינדקס אין נתוני שקית או קרטון.
